# UniMe app reference

Every screen of the UniMe app: what it is for, its title and the screens it leads to.

This file is generated by `scripts/generate-app-reference.mjs` from the routes in `unime/src/routes`, the Svelte components of each screen and the English translations in `unime/src/i18n/en/index.ts`. Do not edit it by hand. Change the code, or the names and purposes in `scripts/app-reference-screens.json`, and run `pnpm docs:app-reference`.

## How to read an entry

- The line under the name gives the route of the screen and the file that implements it. A part in square brackets, as in `/credentials/[id]`, is a parameter.
- The paragraph below it says what the screen is for. It is written by hand.
- **Title** is the English title in the bar at the top of the screen, for a screen that sets one.
- **Opens** lists the screens whose route the code of this screen names, and **Opened from** lists the screens that name this one. A route in the code is nearly always the target of a link or a redirect, but the lists also include a route that the code only compares with. A screen that the backend opens, such as a prompt, says so in its purpose.
- The buttons and texts of a screen are not listed. The file of the screen is the place to look them up.

## Start and unlock

What the app shows when it starts, before the wallet is open.

### Start screen

`/` in `unime/src/routes/+page.svelte`

Shows the UniMe logo while the app loads its state. The backend then redirects: a new wallet goes to onboarding, an existing wallet to the lock screen.

### Lock screen

`/prompt/password-required` in `unime/src/routes/prompt/password-required/+page.svelte`

Opened by the backend when the wallet is locked. The user unlocks it with the password. "Forgot password?" resets the app and removes all data, after a confirmation.

## Scan and exchange

Scanning a QR code or opening a link starts an exchange with an issuer or a verifier. The backend then opens the screens below one after the other. The progress and the result of an exchange show in a sheet on top of the current screen.

### Scan tab

`/scan` in `unime/src/routes/(app)/scan/+page@.svelte`

The second tab in the bar at the bottom. It opens the camera and waits for the QR code of an issuer or a verifier. Without camera permission it offers to open the device settings. In developer mode the value of a QR code can be pasted instead.

- **Opens:** [Me tab](#me-tab), [Activity tab](#activity-tab)

### Connection request

`/prompt/accept-connection` in `unime/src/routes/prompt/accept-connection/+page.svelte`

Opened by the backend when an organization starts an exchange. It shows who is asking: name, logo, website with its domain label, public credentials ("Certifications" in the app) and ecosystems. For an organization the user already knows, it shows the interaction history instead of the warning for new connections. The user accepts or rejects the connection.

- **Title:** "Connection Request"
- **Opens:** [Me tab](#me-tab), [Requester certifications](#requester-certifications), [Requester ecosystems](#requester-ecosystems), [Requester certification details](#requester-certification-details), [Requester ecosystem details](#requester-ecosystem-details)
